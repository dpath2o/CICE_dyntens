## Questions

After the [box01 tests](box01_dev_dynamic_tensile_strength.md), can we still run CICE/Icepack on the global grid, and does setting $g=1$ give the same results as switching dynamic tensile strength off?

The grid is `/g/data/gv90/da1339/grids/ACCESS-OM3-025_Cgrid.nc`, with 1440×1080 cells. Unlike box01, this test uses the normal atmosphere and ocean forcing, thermodynamics and evolving floe-size distribution. The two runs keep these settings identical. The only physical switch that differs is `use_dyntens`.

| Run | Question it answers | Setting | Reference namelist |
|---|---|---|---|
| `dt_g0_off` | Does the global model still complete with the new code present but dynamic tensile strength switched off? | `use_dyntens=.false.` | [ice_in.off](../../global_tests/G0/reference/off/ice_in) |
| `dt_g0_unity` | If we enable the new coefficient but set $g=1$, do we get the same output as the off run? | `use_dyntens=.true.`, `dyntens_g_mode='constant'`, `dyntens_g_const=1` | [ice_in.unity](../../global_tests/G0/reference/unity/ice_in) |

Both runs have FSD-based coefficient diagnostics switched off. This isolates the identity $K_{T,\mathrm{eff}}=K_T$ without introducing the FSD checking policy that we will assess in G1. Both use the same executable and the same 1 September 2000 restart, and stop on 3 September after 96 half-hour timesteps.

## Settings and run procedure

The [global overview](global_dev_dynamic_tensile_strength.md#reference-configuration) records the grid, input paths, physics switches and dates. G0 keeps the inherited **constant wave spectrum**. It does not yet test the WHACS data pathway.

The workflow creates configurations under `global_tests/G0/` and keeps output under `/g/data/gv90/da1339/cice-dirs/runs/`. It builds off once and copies that executable to unity. The old global case and its archived output are kept.

The commands below reproduce fresh cases. **The recorded G0 runs are already complete; use analysis and the notebook with them rather than submitting them again.** Preparation refuses existing case/run folders.

### Create, build and submit

```bash
(
set -euo pipefail
cd /g/data/gv90/da1339/src/CICE_dyntens
git pull --ff-only origin dev
load_modules

runs=/g/data/gv90/da1339/cice-dirs/runs
restart="$runs/dyntens01/restart/iced.2000-09-01-00000.nc"
# If the preserved input restart is elsewhere, change only the line above.
python CICE_testing/scripts/g0_global_workflow.py prepare     --repo "$PWD" --runs "$runs" --restart "$restart"

(cd global_tests/G0/dt_g0_off; ./cice.build)
[[ -x "$runs/dt_g0_off/cice" ]]
cp -p "$runs/dt_g0_off/cice" "$runs/dt_g0_unity/cice"
sha256sum "$runs/dt_g0_off/cice" "$runs/dt_g0_unity/cice"

for name in dt_g0_off dt_g0_unity; do
    (cd "global_tests/G0/$name"; qsub ./cice.run | tee g0-job-id.txt)
done
)
```

Check `qstat -u da1339`. Analyse after both jobs have finished.

## Arctic and Antarctic results table

The [G0 notebook](../../CICE_testing/notebooks/G0.ipynb) now summarises the final daily file, `iceh.2000-09-02.nc`, for off and unity. It displays and saves:

- Ice area, ice extent, ice volume and mean ice-covered thickness for each hemisphere.
- Minimum, ice-area-weighted mean, maximum and standard deviation of available T-cell strength and deformation fields, along with the difference between runs and the largest cell difference.

For these tables, circum-Arctic means all ocean cells north of the equator and circum-Antarctic means all ocean cells south of it. This includes the surrounding seasonal ice seas rather than silently excluding cells below an arbitrary polar latitude. Set `latitude_cutoff` to a different value if a narrower region is needed, and record that choice.

The final file is a **daily mean**, covering the last day of the run; it is not an instantaneous snapshot at the stopping time. The notebook records the file's time and bounds. Ice extent is calculated from daily mean concentration using a 15% threshold. Ice area is $\sum A_i a_i$, ice volume is $\sum A_i h_i$ (`hi` is volume per grid-cell area), and mean ice-covered thickness is total volume divided by total ice area. Strength/deformation statistics use ice-area weights on cells with daily mean concentration at least 15%; the table reports how much selected ice has valid values.

`hs` and `Tsfc` were not requested in this run's history files, so the notebook does not invent them. Velocity fields lie on a different grid; the table does not silently mix them with T-cell weights. Optional fields that were not written or use another grid are listed in the summary record.

The regional tables make the result easier to read, but are not a substitute for the exact comparison of all five files. Equal averages alone can hide local differences. A passed G0 comparison should also give zero differences in these tables. The tables still need to be generated on Gadi; no regional numbers are inserted here without reading those files.

There is no conceptual G0 figure to regenerate. The notebook imports no plotting library, reads a small set of variables in row chunks, and runs NetCDF processing in a separate process. It writes CSV tables and a JSON record, including input hashes. The old screenshot shows a kernel restart during the import cell; it does not identify the underlying cause.
